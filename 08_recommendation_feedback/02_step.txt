Module: Recommendation and Feedback
Main workflow

1. Receive a validated final decision from the Decision and LLM Engine.
2. Build the response with action, compatibility_status, explanation, parts list, setup steps, sources, and freshness.
3. Show information in this order: recommended action, reason, alternatives, and detailed sources.
4. Check the schema, language, retailer links, and accessibility text.
5. Send the result to the backend and Web App.
6. Send a live update when price or stock changes, but only with user consent.
7. Let the user open details, swap a part, ask a question, or send feedback.
8. Store explicit feedback separately from automatic telemetry.
9. Use a pseudonymous ID and follow the retention policy.
10. Start a new data and compatibility check for every updated build (a swapped part or a changed budget).
11. Send incorrect or unsafe reports (e.g. a wrong wattage calculation) to a human safety-review queue.
12. Use reviewed feedback for evaluation or retraining. Do not learn directly from live feedback.

Feedback loop
- New question -> PC Build AI Agent
- Updated budget or part -> New data collection and compatibility check
- Unsafe/incorrect report -> Safety review and operator alert
